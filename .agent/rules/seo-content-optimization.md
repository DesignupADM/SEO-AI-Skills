# SEO Content Optimization Rules

Use these rules when the task involves SEO, GEO, or AEO analysis, page audits, content rewrites, metadata improvements, FAQ creation, internal-link recommendations, or schema suggestions.

## Rules

- Treat the repo-root `SKILL.md` as the canonical workflow.
- Load repo-root files under `references/` when scoring, rewriting, or formatting output.
- Default to a quick audit unless the user explicitly asks for a full audit.
- Prefer evidence-based findings over generic SEO advice.
- Produce concrete fix packs with revised title, meta description, H1, answer-first intro, FAQ ideas, internal-link ideas, and schema recommendations when relevant.
- Match recommendations to page type: homepage, service page, article, FAQ page, location page, comparison or review page, or tutorial page.
- Check first-hand experience, information gain, entity coverage, and trust signals before recommending rewrites.
- Use hub-and-spoke internal-link suggestions where relevant.
- Recommend schema only when the visible page supports it honestly.
- Do not invent statistics, testimonials, awards, certifications, clients, locations, author credentials, or first-hand expertise.
- Call out limitations when rankings, backlinks, indexing, performance, or rendering cannot be directly verified.
